# Mira 调度推演

在 Mira 桌面版新建项目对话并选中解压后的附件目录。每步完成后保存对应的原始执行输出；如当前会话没有脚本执行能力，标明限制，在本地终端执行并上传输出，保留执行位置。

## 1. 运营日交接

> 先把 service_days.csv 当作两个时钟和两类乘客的账本。告诉我时间零点、配对主键、单位与取消标志。检查每站服务日能否一一对应。找出到达与发车两列边际分布相同的一对情景，输出所用比较规则。

## 2. 调度员四策回放

> 固定输入，运行 python analyze.py service_days.csv。对同向延误的第 3 天，手算步行结束分钟与接续缺口，给出等候上限为 0、1、2、3 时的实际等待和接住人数。将同一规则应用于全部服务日。出现超限等待就回退到单日计算。

## 3. 两本账对质

> 执行 python verify.py，打开 replay.json 与 result.json，按站比较准点与限等两分钟下的接续率、换乘人分钟和车上人分钟。核对晚班取消记录的接住人数为 0，解释两张成本表分别是谁承担。

## 4. 权重听证

> 执行 python stress.py。选同向延误情景，找出车上延误需折算多少倍才能让两种策略打平。给出分子、分母、临界值与模型局限。输出一份可审阅的调度简报，只把模拟回放结论写入简报，保留原输出以便分享。

## 补充轮 · 复核实验 v2

> 先从 new_service_days.csv 抽查一日，分别手算准点发车、精准预估和乐观预估时的两本账。执行 forecast.py，核对同一批服务日和相同噪声抽样。呈现净节省的中位数、第10与第90百分位，点名一次徒等但没人赶上的例子。
